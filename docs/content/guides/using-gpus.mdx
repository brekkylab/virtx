The server gives a sandbox the host's GPU through Vulkan, on every host.
The host needs a Vulkan loader, and the image needs the guest's half of Vulkan.

## Create a GPU sandbox

Set `gpu=True` when creating a sandbox.
`gpu_memory_mib` sets how much memory the GPU may hold, apart from the sandbox's own memory, 8 GiB when left out.
This builds an image with the guest's Vulkan packages, then checks the GPU with `vulkaninfo`:

<Tabs syncKey="lang">
<TabItem label="Python">

```python
recipe = Recipe("alpine:latest").run(
    # The Vulkan loader, the venus driver that reaches the host's GPU, and vulkaninfo.
    "apk add --no-cache vulkan-loader mesa-vulkan-virtio vulkan-tools"
)
await client.build_image(recipe, "vulkan:latest").complete(print=True)
sandbox = await client.create_sandbox("vulkan:latest", gpu=True, gpu_memory_mib=8192)
await sandbox.exec(["vulkaninfo", "--summary"]).complete(print=True)
```

</TabItem>
<TabItem label="Node.js">

```js
const recipe = new Recipe('alpine:latest').run(

  'apk add --no-cache vulkan-loader mesa-vulkan-virtio vulkan-tools'

await client.buildImage(recipe, 'vulkan:latest').complete({ print: true })
const options = { gpu: true, gpuMemoryMib: 8192 }

```

</TabItem>
<TabItem label="Rust">

```rust
let recipe = Recipe::new("alpine:latest").step(
    // The Vulkan loader, the venus driver that reaches the host's GPU, and vulkaninfo.
    "apk add --no-cache vulkan-loader mesa-vulkan-virtio vulkan-tools",
);
client.build_image(recipe, "vulkan:latest").await?.complete(true).await?;
let args = SandboxCreateArgs::new("vulkan:latest")
    .gpu(true)
    .gpu_memory_mib(8192);
let sandbox = client.create_sandbox(&args).await?;
let job = sandbox.exec(&SandboxExecArgs::new(["vulkaninfo", "--summary"])).await?;
job.complete(true).await?;
```

</TabItem>
</Tabs>

The host's GPU appears in the guest as `Virtio-GPU Venus (<the host's GPU>)`.
A server built without GPU support refuses a GPU sandbox rather than run it on the CPU, and `gpu_memory_mib` without `gpu` is refused too.

## Guest packages

| Component | Alpine | Debian |
| --- | --- | --- |
| Vulkan loader (`libvulkan.so.1`) | `vulkan-loader` | `libvulkan1` |
| venus driver | `mesa-vulkan-virtio`, 3.24 or later | `mesa-vulkan-drivers`, trixie or later |

- **Install the loader yourself.** Without it, no program in the guest finds a Vulkan device, whatever the host has.
  Debian's `vulkan-tools` brings it along; Alpine's does not.
  Name the loader rather than relying on another package to install it.
- **An image with no venus driver still runs on the CPU.** Debian bookworm's Mesa has no venus, so Vulkan falls back to `llvmpipe`, a software renderer.
  Check the `deviceName` your program selects.

See [Working with images](/docs/guides/images/) for building the guest image, and [Running commands](/docs/guides/running-commands/) for reading command output.

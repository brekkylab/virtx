A package is a sandbox kept under a name, made as many times as it is asked for, by the members of its project and by whom its access lets in.
A `Package` has its `id`, its `name`, the `sandbox` it makes, `max`, `access`, `origins` and `limits` (in Rust, `id()`, `name()` and `info()`).
See [Making packages](/docs/tutorials/packages/), [Letting your users in](/docs/tutorials/package-access/) and [Building an app on a package](/docs/tutorials/app-client/).

| Member | Does |
| --- | --- |
| [`put_package`](#put_package) | Keeps a package under `name`, made or replaced in whole. |
| [`list_package`](#list_package) | The project's packages, or the one an `id` or name names. |
| [`create_sandbox`](#create_sandbox) | Makes a sandbox of a package. |
| [`list_sandbox`](#list_sandbox) | The sandboxes made of a package that the client's credentials made. |
| [`remove`](#remove) | Removes the package; the sandboxes made of it stay. |
| [`AppClient.connect`](#appclientconnect) | Makes a sandbox of a package as an app's user, and reaches it as them. |
| [`AppClient.resume`](#appclientresume) | Reaches again a sandbox the user made, as them. |
| [`AppClient.close`](#appclientclose) | Closes the client, leaving its sandbox. |
| [`AppClient.remove`](#appclientremove) | Removes its sandbox, and closes the client. |

## `put_package`

Keeps the package `name`, made or replaced in whole: each sandbox made of it is made of `image` as [`create_sandbox`](/docs/sdk/sandboxes/#create_sandbox) makes one with the same options, but `name` and a port on local, which each sandbox is given as it is made.
Its image and volumes have to be in the project already.
Replacing a package keeps its `id`, and changes no sandbox made of it.

- `max` is how large one its access let in may resize a sandbox they made of it, each no less than what the package makes it with. One left out holds them to the size the sandbox was made with.
- `access` is who beside the project's members may make one, each a `JwtAccess`: whoever sends a JSON Web Token `issuer` signed for `audience` and carrying each of `claims`, which they then reach the sandbox with.
- `origins` are the web pages they may make one from, and reach it from, each as `https://app.example`.
- `limits` is how many sandboxes made of it by those `access` lets in may live at once: `sandboxes`, all of theirs, and `per_subject`, each one's.

<Tabs syncKey="lang">
<TabItem label="Python" icon="seti:python">

```python
async def put_package(
    name: str, image: str | ImageName, *,
    # ... every option of create_sandbox but name ...
    max: Mapping[str, int] | None = None,
    access: Iterable[JwtAccess] = (),
    origins: Iterable[str] = (),
    limits: PackageLimits | None = None,
) -> Package

@dataclass(frozen=True)
class JwtAccess:
    issuer: str
    audience: str
    jwks: str | None = None
    claims: Mapping[str, Any] = {}

@dataclass(frozen=True)
class PackageLimits:
    sandboxes: int | None = None
    per_subject: int | None = None
```

## `create_sandbox`

Makes a sandbox of the package, answered as a `Sandbox`.
`create_package_sandbox` on the client does the same for a package by its `id` or name.

- `name` finds it again with `find_sandbox`. Only a member of the project may give one; anyone else is refused with `400`.
- `ports` are its ports on local, each `on="local"`, beside the ports in the sandbox the package gives it. A port in the sandbox is refused with `400`.

## `list_sandbox`

The sandboxes made of the package that the client's credentials made: to a member of the project, every one; to one its access lets in, those made with the same issuer and subject, as it lets them in now.
A request with no credentials is refused with `401`.
`list_package_sandbox` on the client does the same for a package by its `id` or name.
A server that takes no credentials answers none of this.

## `AppClient.connect`

Makes a sandbox of the package `package`, by its id, on the server at `url`, as `auth` lets in: a bearer token of the issuer its access names, such as the ID token your app's user signed in with.
`ports` are its ports on local, each `on="local"`, beside those the package gives it in the sandbox.
From then on the client sends `auth` with every request, and its `sandbox` reaches that sandbox: `auth` reaches the sandboxes the user made of the package, and nothing else.
Keep the sandbox's `id` to come back to it with [`resume`](#appclientresume).

It is refused as making the sandbox is: `401` or `403` for one the package does not let in, `429` past its limits, and `400` for a port in the sandbox.

## `AppClient.resume`

Reaches again the sandbox `sandbox`, one the user made of the package `package` as `auth` lets in, such as [`list_sandbox`](#list_sandbox) finds.
It is refused with `401` or `403` for a sandbox they did not make, or one removed.

virtx runs tasks in disposable Linux VMs from your code. Use it for jobs with dependencies you do not want to install on your machine, or code you do not want to run on it.

A virtx server runs the VMs on your machine or another machine. The client packages for Python, Node.js, and Rust share `libvirtx_core`. Client and server speak plain HTTP, over TCP or over a server the client starts as a child process.

## Four resources

| Resource | What it keeps |
| --- | --- |
| Image | A manifest and layers from which sandboxes boot, named by a tag or digest. |
| Sandbox | A Linux VM with its own disk and any volumes mounted into it, on a snapshot if given. Its files stay across stops until it is deleted. |
| Snapshot | The writable layer of a sandbox's root filesystem, kept under a name, so the next sandbox starts with what one installed. |
| Volume | Named storage that can be mounted into sandboxes and stays when they are removed. |

Changes in a sandbox are gone when it is removed, except for what it wrote to a snapshot or a volume, or committed to an image.

## Connect to a server

Start with the [cloud quickstart](/docs/quickstart/) to sign in, create an API key, and build and run a sandbox. To start a server as a child process or connect to your own HTTP server, see [Run locally](/docs/local/).

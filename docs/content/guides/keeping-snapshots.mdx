---
title: "Keeping work in snapshots"
description: "Keep what a sandbox writes in a snapshot, read and write its files without a sandbox, and start the next sandbox where the last one left off."
---

import { Tabs, TabItem } from "@astrojs/starlight/components";

A sandbox's root filesystem is its image below, read-only, and a writable layer above, where everything it writes goes.
Without a snapshot, that layer is the sandbox's own and is deleted with it.
A **snapshot** is a writable layer kept under a name: a sandbox made on it writes into it, and the snapshot stays when the sandbox is removed.
The next sandbox made on it starts with everything the last one wrote.

A snapshot's files can also be read and written from your code, with no sandbox running, through the server's files API over WebDAV.
A path there is the path in the guest without its leading `/`: `artifacts/report.txt` in the snapshot is `/artifacts/report.txt` in a sandbox on it.

The example on this page follows an AI agent's task, with two directories in the snapshot:

- `/attachments`: the files the user gave the agent.
- `/artifacts`: the files the agent made.

## Create a snapshot

`create_snapshot` makes an empty snapshot.
`disk_gib` caps how much a sandbox on it can write, and the server picks a name when none is given.

<Tabs syncKey="lang">
<TabItem label="Python">

```python
snapshot = await client.create_snapshot("task-42")
```

</TabItem>
<TabItem label="Node.js">

```js
const snapshot = await client.createSnapshot('task-42')
```

</TabItem>
<TabItem label="Rust">

```rust
let snapshot = client.create_snapshot(Some("task-42"), None).await?;
```

</TabItem>
</Tabs>

## Put the user's files in it

Write the user's input into `attachments` before any sandbox starts.
`write_file` writes a whole file, and its parent directory must exist.

<Tabs syncKey="lang">
<TabItem label="Python">

```python
await snapshot.create_dir_all("attachments")
await snapshot.write_file("attachments/notes.txt", "ship the release on friday\n")
```

</TabItem>
<TabItem label="Node.js">

```js
await snapshot.createDirAll('attachments')
await snapshot.writeFile('attachments/notes.txt', 'ship the release on friday\n')
```

</TabItem>
<TabItem label="Rust">

```rust
snapshot.create_dir_all("attachments").await?;
snapshot
    .write_file("attachments/notes.txt", "ship the release on friday\n", None)
    .await?;
```

</TabItem>
</Tabs>

## Run a sandbox on it

Pass the snapshot to `create_sandbox`.
The sandbox finds the user's files at `/attachments`, and what it writes, here a word count in `/artifacts`, goes into the snapshot.

<Tabs syncKey="lang">
<TabItem label="Python">

```python
sandbox = await client.create_sandbox("alpine:latest", snapshot=snapshot)
cmd = ["sh", "-c", "mkdir -p /artifacts && wc -w /attachments/notes.txt > /artifacts/report.txt"]
await sandbox.exec(cmd).complete()
await sandbox.remove()
```

</TabItem>
<TabItem label="Node.js">

```js
const sandbox = await client.createSandbox('alpine:latest', { snapshot })
const cmd = ['sh', '-c', 'mkdir -p /artifacts && wc -w /attachments/notes.txt > /artifacts/report.txt']
await sandbox.exec(cmd).complete()
await sandbox.remove()
```

</TabItem>
<TabItem label="Rust">

```rust
let args = SandboxCreateArgs::new("alpine:latest").snapshot(snapshot.name());
let sandbox = client.create_sandbox(&args).await?;
let cmd = ["sh", "-c", "mkdir -p /artifacts && wc -w /attachments/notes.txt > /artifacts/report.txt"];
sandbox.exec(&SandboxExecArgs::new(cmd)).await?.complete(false).await?;
sandbox.remove().await?;
```

</TabItem>
</Tabs>

One sandbox holds a snapshot at a time.
While it does, the snapshot's files are the sandbox's: reading them through the snapshot is refused with `423`, and removing the snapshot with `409`, until the sandbox is removed.
To read files while the sandbox runs, read them through the sandbox instead, with the same calls.

## Read what it made

With the sandbox removed, the agent's output is in the snapshot's `artifacts`.
Reading it from the snapshot needs no sandbox at all: the server reads the snapshot's disk itself, with no VM to boot.
A sandbox's own files, by contrast, are read through its VM, which is booted again if it had been stopped.
So when a task is done, removing the sandbox and reading its output from the snapshot is usually the cheaper way.

<Tabs syncKey="lang">
<TabItem label="Python">

```python
for entry in await snapshot.read_dir("artifacts"):
    print(entry.name, entry.metadata.size)
print(await snapshot.read_text("artifacts/report.txt"))
```

</TabItem>
<TabItem label="Node.js">

```js
for (const entry of await snapshot.readDir('artifacts')) {
  console.log(entry.name, entry.metadata.size)
}
console.log(await snapshot.readText('artifacts/report.txt'))
```

</TabItem>
<TabItem label="Rust">

```rust
for entry in snapshot.read_dir("artifacts").await? {
    println!("{} {}", entry.name, entry.metadata.size);
}
println!("{}", snapshot.read_text("artifacts/report.txt").await?);
```

</TabItem>
</Tabs>

## Pick up where it left off

A new sandbox on the same snapshot starts with both directories as the last one left them, and with anything else it installed or changed.
The user can add a file to `attachments` in between, and the agent carries on with it.

<Tabs syncKey="lang">
<TabItem label="Python">

```python
await snapshot.write_file("attachments/todo.txt", "write the changelog\n")

sandbox = await client.create_sandbox("alpine:latest", snapshot=snapshot)
await sandbox.exec(["ls", "/attachments", "/artifacts"]).complete(print=True)
```

</TabItem>
<TabItem label="Node.js">

```js
await snapshot.writeFile('attachments/todo.txt', 'write the changelog\n')

const sandbox = await client.createSandbox('alpine:latest', { snapshot })
await sandbox.exec(['ls', '/attachments', '/artifacts']).complete({ print: true })
```

</TabItem>
<TabItem label="Rust">

```rust
snapshot
    .write_file("attachments/todo.txt", "write the changelog\n", None)
    .await?;

let args = SandboxCreateArgs::new("alpine:latest").snapshot(snapshot.name());
let sandbox = client.create_sandbox(&args).await?;
let job = sandbox.exec(&SandboxExecArgs::new(["ls", "/attachments", "/artifacts"])).await?;
job.complete(true).await?;
```

</TabItem>
</Tabs>

When the task is done, remove the sandbox, then the snapshot with `remove`, which deletes everything in it.

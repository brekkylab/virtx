## Forward a TCP port

Pass `ports` when creating a sandbox to open TCP ports in it. Each port is returned with a URL by `create_sandbox` and `start_sandbox`. `sandbox.open_port(port)` opens one later and returns the port, with its `url`. The stdio server opens ports only at creation: it can't open or close one later.

`PortForwarder.open` uses that URL and the client's session to put the port at an address on this machine's loopback. Any TCP client can connect to the forwarder's `address`. A stopped sandbox's port takes no connections, and a connection to it does not start the sandbox.

<Tabs>
<TabItem label="Python">

```python
from virtx import PortForwarder

sandbox = await client.create_sandbox("jq:latest", ports=[8000])
with PortForwarder.open(client, sandbox.ports[0].url) as forwarder:
    print("reach it at", forwarder.address)
port = await sandbox.open_port(9000)  # kept in sandbox.ports too
# its url reaches it no more, and it leaves sandbox.ports
await sandbox.close_port(9000)
```

</TabItem>

let mut args = SandboxCreateArgs::new("jq:latest");

let forwarder = PortForwarder::open(&client, &sandbox.ports[0].url)?;

Opening a port through the sandbox adds it to `sandbox.ports`. Closing one drops it from that list. In Rust, `sandbox.ports` stays what the create call answered: the client's port calls return the port, or nothing, and do not touch it.

## Open an HTTP port

A port can include a label and use HTTP. Put `PortSpec(5173, label="dev server", protocol="http")` in `ports`, or call `open_port(5173, label="dev server", protocol="http")`. On virtx cloud, an HTTP port's URL is an HTTPS address that opens in a browser. The HTTP server you run yourself answers every port with a `virtx.tcp` WebSocket URL, for a `PortForwarder`.

`ports` can mix plain TCP ports and HTTP specifications, such as `[8000, PortSpec(5173, protocol="http")]`. Node.js takes `{ port, label, protocol }` objects there. Rust takes a `PortSpec`, with `8080.into()` for a plain port.

## Close or change a port

`sandbox.close_port(port)` closes a port. Its URL no longer reaches it, and the port is not opened again when the sandbox starts. Node.js calls this `closePort`.

The client method is `close_sandbox_port(id, port)`, or `closeSandboxPort` in Node.js. The client method is the only way to close a port in Rust.

To change a TCP port to HTTP, close it and open it again. It gets another URL.

On virtx cloud, port 5900 is the sandbox's desktop in the console. It is open in every sandbox, and closing it is refused with `409`, code `in_use`.

## Connect to an address directly

On virtx cloud, a TCP port can also have a public `address`, in `host:port` form, that a TCP client reaches without a `PortForwarder`. A port gets one when its first inbound rule is added in the console, and the address takes connections only from the sources its rules name. An organization can hold 20 public addresses by default; the rule that would need one more is refused with `429`, code `quota`.

An HTTP port takes inbound rules too, but gets no public address. It opens with one rule, for anywhere: anyone with the URL reaches it. Replace that rule with the sources the port is for, and its URL answers only requests from them, refusing others with `403`; with its rules all removed, it refuses everyone. A server you run yourself and port 5900 have no inbound rules.

The URL is secret; the direct address is not. A service reached through a direct address must still authenticate whoever connects.

Ports carry connections into a sandbox. A sandbox created with `network=False` keeps its ports but can't open outbound connections; see [Run commands](/docs/guides/run-commands/#disable-outbound-networking).

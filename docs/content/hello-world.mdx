In this tutorial you install the VirtX client and run a program that prints `Hello, world!` from inside a sandbox.

## Before you begin

- Python 3.11 or later, Node.js 22 or later, or Rust 1.89 or later.
- A server to run the sandbox on. The program below starts one on your machine, which requires Linux with KVM, macOS on Apple silicon, or Windows 11 (x86_64). See the [requirements](/docs/installation/#requirements).

<Aside type="caution">
If your machine can't run VMs, for example an Intel Mac, use [VirtX cloud](#virtx-cloud) or [your own server](#your-own-server) instead, and change one line of the program as that section shows.
</Aside>

## Step 2: Run a command in a sandbox

Save this program and run it:

<Tabs syncKey="lang">
<TabItem label="Python" icon="seti:python">

```python
import asyncio

from virtx import Client


async def main() -> None:
    async with Client.spawn() as client:
        await client.pull_image("alpine:latest").complete()
        sandbox = await client.create_sandbox("alpine:latest")
        try:
            await sandbox.exec(["echo", "Hello, world!"]).complete(print=True)
        finally:
            await sandbox.remove()


asyncio.run(main())
```

</TabItem>
<TabItem label="Node.js" icon="node">

```js
const { Client } = require('@brekkylab/virtx')

async function main() {
  const client = Client.spawn()
  try {
    await client.pullImage('alpine:latest').complete()
    const sandbox = await client.createSandbox('alpine:latest')
    try {
      await sandbox.exec(['echo', 'Hello, world!']).complete({ print: true })
    } finally {
      await sandbox.remove()
    }
  } finally {
    await client.close()
  }
}

main()
```

</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
use virtx::{Client, SandboxCreateArgs, SandboxExecArgs};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let client = Client::spawn_virtx([] as [&str; 0]).await?;
    client.pull_image("alpine:latest", None).complete(false).await?;
    let sandbox = client
        .create_sandbox(&SandboxCreateArgs::new("alpine:latest"))
        .await?;
    let result = sandbox
        .exec(&SandboxExecArgs::new(["echo", "Hello, world!"]))
        .complete(true)
        .await;
    sandbox.remove().await?; // remove the sandbox even if the command failed
    result?;
    Ok(())
}
```

</TabItem>
</Tabs>

The program prints:

```text frame="terminal" title="Output"
Hello, world!
```

The first run takes longer, because `Client.spawn()` downloads the server (`virtx-stdio`) and caches it for later runs.

## What the program does

1. `Client.spawn()` starts a VirtX server as a child process of your program. The server stops when the client closes.
2. `pull_image` copies the `alpine:latest` image from Docker Hub to the server. A sandbox can only boot from an image the server already has.
3. `create_sandbox` boots a sandbox from that image.
4. `exec` starts `echo` in the sandbox, and `complete(print=True)` waits for it to finish and prints its output.
5. `remove` deletes the sandbox and everything it wrote.

## Pick a server

The program is the same wherever the server runs. To use another server, replace the line that creates the client.

<img src={clientServer.src} width={clientServer.width} height={clientServer.height} alt="A VirtX client reaches a server that is local, on the client machine; remote, on another machine; or in the cloud, hosted by VirtX." />

### VirtX cloud

1. Sign in to the [console](/signin/) with Google.
2. Create an API key in a project. Every organization starts with a project named `default`. The console shows the key only once.
3. Set the key in your environment:

   ```sh
   export VIRTX_API_KEY=vx_sk_...
   ```

4. Replace `Client.spawn()` with a client that connects to VirtX cloud with the key:

<Tabs syncKey="lang">
<TabItem label="Python" icon="seti:python">

```python
import os

from virtx import BearerAuth

async with Client.connect(
    "https://cloud.virtx.sh",
    BearerAuth(os.environ["VIRTX_API_KEY"]),
) as client:
```

</TabItem>
<TabItem label="Node.js" icon="node">

```js
const client = Client.connect(
  'https://cloud.virtx.sh',
  { type: 'bearer', token: process.env.VIRTX_API_KEY }
)
```

</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
use virtx::Auth;

let client = Client::connect(
    "https://cloud.virtx.sh",
    Auth::Bearer { token: std::env::var("VIRTX_API_KEY")? },
    None,
)?;
```

</TabItem>
</Tabs>

An API key belongs to one project, so you don't pass a project in code. `cloud.virtx.sh` answers from the VirtX cloud region nearest to the machine the program runs on.

### Your own server

Use this when your team runs `virtx-server-tcp`, as [Running your own server](/docs/tutorials/self-hosting/) describes.

1. Sign in to the server once. `uvx` (or `pipx run`) and `npx` run the `virtx` command without installing it. To install it, see [Installing](/docs/reference/cli/#installing).

   ```sh
   uvx virtx login https://virtx.example
   # or
   npx -y @brekkylab/virtx login https://virtx.example
   ```

2. Replace `Client.spawn()` with a client that connects to the server. `CommandAuth` runs `virtx token` to get a token, and runs it again whenever the token expires:

<Tabs syncKey="lang">
<TabItem label="Python" icon="seti:python">

```python
from virtx import CommandAuth

async with Client.connect(
    "https://virtx.example",
    CommandAuth("uvx", ("virtx", "token", "--json")),
) as client:
```

</TabItem>
<TabItem label="Node.js" icon="node">

```js
const client = Client.connect(
  'https://virtx.example',
  { type: 'command', program: 'npx', args: ['-y', '@brekkylab/virtx', 'token', '--json'] }
)
```

</TabItem>
<TabItem label="Rust" icon="seti:rust">

```rust
use virtx::Auth;

let client = Client::connect(
    "https://virtx.example",
    Auth::Command { program: "uvx".into(), args: vec!["virtx".into(), "token".into(), "--json".into()] },
    None,
)?;
```

</TabItem>
</Tabs>

See [Signing in](/docs/reference/cli/#signing-in) in the CLI reference for `login`, `token` and `logout`.

## If something goes wrong

1. **`boot_failed`**

   **Cause:** Your machine can't boot a VM.

   **Fix:** See [Troubleshooting](/docs/installation/#troubleshooting) in Installation.

2. **`no virtx-stdio release ... is published for macos-x86_64`**

   **Cause:** Intel Macs can't run sandboxes locally.

   **Fix:** Use [VirtX cloud](#virtx-cloud).

## What VirtX is

VirtX runs Linux microVMs on your machine or in the cloud, and lets you ship them as a service.

Run code in a sandbox that you don't want to run on your own machine, such as code an AI agent wrote.
When you build an app on VirtX, each of its users gets a sandbox of their own.

## How the pieces fit

| Term | What it is |
| --- | --- |
| **Client** | The `virtx` package your code imports. It sends every request to a server. |
| **Server** | The program that runs sandboxes. It runs in one of three places (see below). |
| **Sandbox** | A Linux microVM that the server boots from an image. What a sandbox writes outside a volume is deleted when you remove it. |
| **Image** | The read-only filesystem a sandbox boots from, such as `alpine:latest`. You pull images from a registry or build them. |
| **Job** | A command running in a sandbox, or an image build, pull or push. A job keeps running if your program stops reading it, and its output is kept in a log you can read again. |
| **Volume** | Storage that exists apart from any sandbox. Mount it into sandboxes to keep files after they are removed, or to share files between them. |
| **Project** | A group of sandboxes, images and volumes on a server. You can share a project with teammates. |
| **Package** | A sandbox kept under a name in a project, which members, and anyone else it lets in, make as many sandboxes of as they need. Each who is let in reaches only the sandbox they made. |

The server can run in three places. Your code is the same in each; only the line that creates the client changes.

| Where the server runs | Use it when | Your machine needs |
| --- | --- | --- |
| **On your machine** (`Client.spawn()`) | You work alone and your machine can run VMs. The client starts the server for you. | Linux with KVM, macOS on Apple silicon, or Windows 11 (x86_64) |
| **VirtX cloud** (`Client.connect()` to `https://cloud.virtx.sh`) | You don't want to run VMs yourself. GPUs are not available on VirtX cloud yet. | Only the client |
| **Your own server** (`Client.connect()`) | A team shares one machine that runs `virtx-server-tcp`. | Only the client |

The guest in every sandbox is Linux, whatever operating system the server's machine (the host) runs.

## Before you start

You need Python 3.11 or later, Node.js 22 or later, or Rust 1.89 or later.
To run sandboxes on your own machine, it must also meet the [requirements](/docs/installation/#requirements) in Installation.

## Tutorials

Each tutorial covers one feature of VirtX in depth:

- [Working with images](/docs/tutorials/images/): build, pull, push, tag and prune images.
- [Setting up sandboxes](/docs/tutorials/setting-sandboxes/): CPUs, memory, disk, network and names, and resizing a sandbox later.
- [Running commands](/docs/tutorials/running-commands/): run commands, stream their output, write to stdin, and stop them.
- [Reading and writing files](/docs/tutorials/reading-writing-files/): move files in and out without running a command.
- [Networks and ports](/docs/tutorials/networks-ports/): control outbound access and reach services in a sandbox.
- [Mounting volumes](/docs/tutorials/mounting-volumes/): keep files after a sandbox is removed, and mount Notion, Google Drive or OneDrive.
- [Using GPUs](/docs/tutorials/using-gpus/): give a sandbox the host's GPU through Vulkan.
- [Using built-in programs](/docs/tutorials/built-in-programs/): give a sandbox VirtX's built-in programs at `/abin`, which run on any image.
- [Managing projects](/docs/tutorials/projects/): organize resources and share them with your team.
- [Running your own server](/docs/tutorials/self-hosting/): serve VirtX to your team, with users signed in through your OpenID Connect provider.
- [Making packages](/docs/tutorials/packages/): keep a sandbox under a name, and make as many sandboxes of it as you need.
- [Letting your users in](/docs/tutorials/package-access/): let people who are not members make a sandbox of a package, each reaching only their own.
- [Building an app on a package](/docs/tutorials/app-client/): make a sandbox of a package from your app with `AppClient`, use it with its grant, and come back to it later.

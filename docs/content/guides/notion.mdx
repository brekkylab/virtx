Mount a Notion workspace in a sandbox, and its pages and databases appear as read-only files an agent browses and reads with its usual filesystem tools.
The files are read from Notion as they are opened, not copied in, so they follow the workspace as it changes.

## Connect Notion

1. As a workspace owner, create an internal connection and give it the **Read content** capability.
2. On the top-level page you want to expose, open the **•••** menu, select **Add connections**, and choose your connection.
3. Set `NOTION_API_KEY` in the environment of the program running the virtx client, using the API token from the connection's **Configuration** tab.

<Aside type="caution">
These steps follow Notion's settings as this guide was written, and Notion may rename or move them.
If a menu or tab differs, follow the [Notion authorization guide](https://developers.notion.com/guides/authorization/overview#internal-connection-auth-flow-set-up).
</Aside>

## Mount and list pages

With a connected client, mount Notion at `notion` inside a new volume, then mount that volume at `/context` in the sandbox. The command lists the top-level pages visible to the connection.

The virtx server calls the Notion API, so a self-hosted server needs access to `api.notion.com` and the sandbox can run with its network disabled.

<Tabs syncKey="lang">
<TabItem label="Python">

```python
import os

from virtx import NotionSource, SandboxVolume

volume = await client.create_volume()
await volume.mount("notion", NotionSource(os.environ["NOTION_API_KEY"]))

sandbox = await client.create_sandbox(
    "alpine:latest",
    volumes=[SandboxVolume(volume, "/context", readonly=True)],
    network=False,
)
await sandbox.exec(["ls", "/context/notion/pages"]).complete(print=True)
```

</TabItem>

<TabItem label="Rust">

```rust
use virtx::{MountSource, SandboxCreateArgs, SandboxExecArgs, SandboxVolume};

let volume = client.create_volume(None::<String>).await?;
let source = MountSource::Notion {
    api_key: std::env::var("NOTION_API_KEY")?,
};
volume.mount("notion", source).await?;

let mut args = SandboxCreateArgs::new("alpine:latest").network(false);
args.volumes.push(SandboxVolume {
    volume: volume.name().to_owned(),
    path: "/context".into(),
    readonly: true,
});
let sandbox = client.create_sandbox(&args).await?;
sandbox
    .exec(&SandboxExecArgs::new(["ls", "/context/notion/pages"]))
    .complete(true)
    .await?;
```

## Read a page

Each directory under `/context/notion/pages` has a name of the form `<title>__<page-id>`. Use a name from the listing to run a command like this inside the sandbox.

```sh
cat '/context/notion/pages/<title>__<page-id>/page.json'
```

Read the `markdown` field of `page.json` for the page body. Child pages appear in subdirectories beneath their parent. If the listing is empty, check that the connection has access to a top-level page.

## Read a database

A database in a page appears in the page's directory beside its child pages, named `<title>__db__<database-id>`.
Its `database.json` holds the database's schema in `properties` and one entry per row in `rows`.
Each row carries its `page_id`, its directory name in `dir`, and its values in `properties`, as the Notion API returns them.
The whole index comes from one query, so an agent reads `database.json` to pick rows rather than opening every row's directory.

```sh
cd '/context/notion/pages/<title>__<page-id>/<database>__db__<database-id>'
jq -r '.rows[] | select(.properties.Status.status.name == "Done") | .dir' database.json
```

This prints the directories of the rows whose `Status` is `Done`:

```text
Fix_login_redirect__1c2e4f6a-0b3d-4e5f-8a9b-0c1d2e3f4a5b
Write_release_notes__7d8e9fa0-1b2c-4d3e-9f4a-5b6c7d8e9fa0
```

Each property nests its value under its type's name, such as `status`, `select` or `date`, so match the path to your database's schema.
One row of `database.json` looks like this, trimmed to two properties:

```json
{
  "page_id": "1c2e4f6a-0b3d-4e5f-8a9b-0c1d2e3f4a5b",
  "dir": "Fix_login_redirect__1c2e4f6a-0b3d-4e5f-8a9b-0c1d2e3f4a5b",
  "icon": "🐛",
  "properties": {
    "Name": { "type": "title", "title": [{ "plain_text": "Fix login redirect" }] },
    "Status": { "type": "status", "status": { "name": "Done" } }
  }
}
```

A row is a page like any other: its `page.json` has the same properties and the row's body in `markdown`.

`jq` is not in `alpine:latest`, and a sandbox without a network cannot install it.
Build an image with it as in [Images](/docs/tutorials/images/) and create the sandbox from that.

When you finish, call `remove` on the sandbox and then on the example volume. To keep the volume and disconnect Notion, call `volume.unmount("notion")` after removing the sandbox.

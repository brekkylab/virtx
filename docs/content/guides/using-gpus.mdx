The server gives a sandbox the host's GPU through Vulkan, on every host.
The host needs a Vulkan loader.
The guest's half of Vulkan, the loader and the venus driver that reaches the host's GPU, comes with every sandbox, so the image needs neither.

## Create a GPU sandbox

Set `gpu=True` when creating a sandbox.
`gpu_memory_mib` sets how much memory the GPU may hold, apart from the sandbox's own memory, 8 GiB when left out.
This builds an image with `vulkaninfo`, then checks the GPU with it:

<Tabs syncKey="lang">
<TabItem label="Python">

```python
recipe = Recipe("alpine:latest").run(
    # vulkaninfo, to check the GPU with. Vulkan itself comes with the sandbox.
    "apk add --no-cache vulkan-tools"
)
async for entry in client.build_image(recipe, "vulkan:latest"):
    match entry.entry:
        case Log(line):
            print(line)
        case ImageJobEnd(error=str(error)):
            raise RuntimeError(error)
sandbox = await client.create_sandbox("vulkan:latest", gpu=True, gpu_memory_mib=8192)
async for entry in sandbox.exec(["vulkaninfo", "--summary"]):
    print(entry.entry)
```

<TabItem label="Rust">

```rust
let recipe = Recipe::new("alpine:latest").step(
    // vulkaninfo, to check the GPU with. Vulkan itself comes with the sandbox.
    "apk add --no-cache vulkan-tools",
);
let mut log = client.build_image(recipe, "vulkan:latest").log();
while let Some(entry) = log.next().await {
    match entry?.entry {
        ImageJobEntry::Log(line) => println!("{line}"),
        ImageJobEntry::End(end) if end.error.is_some() => Err(end.error.unwrap())?,
        _ => {}
    }
}
let args = SandboxCreateArgs::new("vulkan:latest")
    .gpu(true)
    .gpu_memory_mib(8192);
let sandbox = client.create_sandbox(&args).await?;
let mut log = sandbox.exec(&SandboxExecArgs::new(["vulkaninfo", "--summary"])).log();
while let Some(entry) = log.next().await {
    println!("{:?}", entry?.entry);
}
```

The host's GPU appears in the guest as `Virtio-GPU Venus (<the host's GPU>)`.
A server built without GPU support refuses a GPU sandbox rather than run it on the CPU, and `gpu_memory_mib` without `gpu` is refused too.

## What the sandbox brings

Every sandbox has `/alib`, a read-only directory of virtx's own libraries, with the Vulkan loader and venus built twice: in `/alib/musl` for images on musl, such as Alpine, and in `/alib/glibc` for images on glibc 2.28 or later, such as Debian and Ubuntu.
When the sandbox starts, the directory for the image's C library goes on `LD_LIBRARY_PATH`, after any the image sets.
In a GPU sandbox, `VK_DRIVER_FILES` names venus from there too, so a program finds the host's GPU whatever the image has installed.

- **An image's own Vulkan driver is passed over in a GPU sandbox.** Set `VK_DRIVER_FILES` in the image to choose another.
- **A program that links the Vulkan loader finds the one in `/alib` before the image's,** and one that opens `libvulkan.so.1` by name does too.

See [Working with images](/docs/guides/images/) for building the guest image, and [Running commands](/docs/guides/running-commands/) for reading command output.

An Android device cannot move into a sandbox: an emulator needs your machine's hardware acceleration, and a phone is plugged into your machine.
`adb` reaches either through a server on your machine, at `127.0.0.1:5037`, which an `adb` elsewhere can be pointed at with `-H`.
So an agent in a sandbox uses the device through a [client port](/docs/tutorials/networks-ports/#client-ports): its `adb` talks to `10.0.2.2:5037`, and the forwarder carries that to the `adb` server on your machine.
This guide takes a screenshot of an emulator and taps on it from a sandbox.

## Start a device to hand over

Start an emulator, or plug in a phone with USB debugging on, and check that `adb` on your machine sees it:

```bash
emulator -avd agent &
adb devices
```

`adb devices` starts the `adb` server if none runs, and lists the device.

<Aside type="caution">
Whatever reaches the `adb` server can do nearly all a person holding the device can: read its photos and files, install apps, and use the apps signed in on it.
It can also open ports between the device and your machine with `adb reverse` and `adb forward`.
Hand the agent an emulator, or a device kept for testing.
</Aside>

## Use it from a sandbox

The sandbox is made with the client port `5037`, gets `adb` from Alpine's packages, and is told where the server is with `ADB_SERVER_SOCKET`, so every `adb` command in it reaches the device on your machine.

<Tabs syncKey="lang">
<TabItem label="Python">

```python
from virtx import ClientPortForwarder

sandbox = await client.create_sandbox("alpine:latest", client_ports=[5037])
await sandbox.exec(["apk", "add", "-q", "android-tools"]).complete(print=True)

async def adb(*args):
    cmd = ["env", "ADB_SERVER_SOCKET=tcp:10.0.2.2:5037", "adb", *args]
    await sandbox.exec(cmd).complete(print=True)

async with await ClientPortForwarder.open(sandbox, 5037):
    await adb("devices")
    await adb("shell", "screencap", "-p", "/sdcard/screen.png")
    await adb("pull", "/sdcard/screen.png", "/root/screen.png")
    await adb("shell", "input", "tap", "540", "1200")

screen = await sandbox.read_file("root/screen.png")
```

<TabItem label="Rust">

```rust
let args = SandboxCreateArgs::new("alpine:latest").client_port(5037);
let sandbox = client.create_sandbox(&args).await?;
let install = SandboxExecArgs::new(["apk", "add", "-q", "android-tools"]);
sandbox.exec(&install).complete(true).await?;

let forwarder = ClientPortForwarder::open(&sandbox, 5037, None).await?;
for args in [
    &["devices"][..],
    &["shell", "screencap", "-p", "/sdcard/screen.png"],
    &["pull", "/sdcard/screen.png", "/root/screen.png"],
    &["shell", "input", "tap", "540", "1200"],
] {
    let cmd = ["env", "ADB_SERVER_SOCKET=tcp:10.0.2.2:5037", "adb"];
    let cmd = SandboxExecArgs::new(cmd.iter().chain(args).copied());
    sandbox.exec(&cmd).complete(true).await?;
}
drop(forwarder);

let screen = sandbox.read_file("root/screen.png", 0, None).await?;
```

`adb devices` lists the emulator, the screenshot lands in the sandbox, and the tap lands on the emulator's screen.
An agent goes on the same way: it reads the screen, from a screenshot or from `adb shell uiautomator dump`, and acts with `adb shell input`.

## When it is not reached

`adb` in the sandbox and the `adb` server on your machine are best of one version: an `adb` that finds a server of another version may try to restart it, which it cannot do on another machine.
Install the same version on both sides, or check `adb version` on each if a command fails so.

A connection to `10.0.2.2:5037` is refused, as one to a closed port is, while no forwarder is open, and while no `adb` server runs on your machine: run `adb devices` there first.
What the forwarder could not reach is logged as a warning, as the [tutorial](/docs/tutorials/networks-ports/#client-ports) says.

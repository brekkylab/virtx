## On virtx cloud: early access

virtx cloud does not offer GPU sandboxes yet. A `create_sandbox` call with `gpu=True` is refused with `501`, code `unsupported` and reason `gpu_unsupported`. The refusal is how early access is asked for: virtx cloud records the request, with what it asked for, for your organization.

[Sign up](/signup/), make an API key, and ask for the sandbox your work needs:

<Tabs>
<TabItem label="Python">

```python
# Raises VirtxError with the 501 refusal; the request is recorded.
await client.create_sandbox("vulkan:latest", gpu=True, gpu_memory_mib=8192)
```

</TabItem>
<TabItem label="Node.js">

```js
// Rejects with a VirtxError carrying the 501 refusal; the request is recorded.
await client.createSandbox('vulkan:latest', { gpu: true, gpuMemoryMib: 8192 })
```

</TabItem>
<TabItem label="Rust">

```rust
// Err(Error::Call(..)) with the 501 refusal; the request is recorded.
let mut args = SandboxCreateArgs::new("vulkan:latest");
args.gpu = Some(true);
args.gpu_memory_mib = Some(8192);
client.create_sandbox(&args).wait()?;
```

</TabItem>
</Tabs>

## On your own machine

On your own machine, the server gives a sandbox the host's GPU through Vulkan, on every host: the host needs a Vulkan loader, and the image the guest's half of Vulkan. Set `gpu=True` when creating a sandbox and use `gpu_memory_mib` to request its memory. Install the guest Vulkan packages in the image:

<Tabs>
<TabItem label="Python">

```python
recipe = Recipe("alpine:latest").run(
    # The Vulkan loader, the venus driver that reaches the host's GPU, and vulkaninfo.
    "apk add --no-cache vulkan-loader mesa-vulkan-virtio vulkan-tools"
)
async for entry in client.build_image(recipe, "vulkan:latest"):
    match entry.entry:
        case Log(line):
            print(line)
        case ImageJobEnd(error=str(error)):
            raise RuntimeError(error)
sandbox = await client.create_sandbox("vulkan:latest", gpu=True, gpu_memory_mib=8192)
async for entry in client.exec_sandbox(sandbox.id, ["vulkaninfo", "--summary"]):
    print(entry.entry)
```

</TabItem>
<TabItem label="Node.js">

```js
const recipe = new Recipe('alpine:latest').run(
  // The Vulkan loader, the venus driver that reaches the host's GPU, and vulkaninfo.
  'apk add --no-cache vulkan-loader mesa-vulkan-virtio vulkan-tools'
)
for await (const entry of client.buildImage(recipe, 'vulkan:latest')) {
  if ('log' in entry) console.log(entry.log)
  else if ('end' in entry && 'error' in entry.end) {
    throw new Error(entry.end.error)
  }
}
const options = { gpu: true, gpuMemoryMib: 8192 }
const sandbox = await client.createSandbox('vulkan:latest', options)
const cmd = ['vulkaninfo', '--summary']
for await (const entry of client.execSandbox(sandbox.id, cmd)) {
  console.log(entry)
}
```

</TabItem>
<TabItem label="Rust">

```rust
let recipe = Recipe::new("alpine:latest").step(
    // The Vulkan loader, the venus driver that reaches the host's GPU, and vulkaninfo.
    "apk add --no-cache vulkan-loader mesa-vulkan-virtio vulkan-tools",
);
let mut log = client.build_image(recipe, "vulkan:latest").log();
while let Some(entry) = log.wait_next() {
    match entry?.entry {
        ImageJobEntry::Log(line) => println!("{line}"),
        ImageJobEntry::End(end) if end.error.is_some() => Err(end.error.unwrap())?,
        _ => {}
    }
}
let mut args = SandboxCreateArgs::new("vulkan:latest");
args.gpu = Some(true);
args.gpu_memory_mib = Some(8192);
let sandbox = client.create_sandbox(&args).wait()?;
let cmd = SandboxExecArgs::new(["vulkaninfo", "--summary"]);
let mut log = client.exec_sandbox(&sandbox.id, &cmd).log();
while let Some(entry) = log.wait_next() {
    println!("{:?}", entry?.entry);
}
```

</TabItem>
</Tabs>

The host's GPU appears in the guest as `Virtio-GPU Venus (<the host's GPU>)`. A server that can't give a GPU refuses the sandbox rather than run it on the CPU.

### Guest packages

| Component | Alpine | Debian |
| --- | --- | --- |
| Vulkan loader (`libvulkan.so.1`) | `vulkan-loader` | `libvulkan1` |
| venus driver | `mesa-vulkan-virtio`, 3.24 or later | `mesa-vulkan-drivers`, trixie or later |

- **Install the loader yourself.** Without it, no program in the guest finds a Vulkan device, whatever the host has. Debian's `vulkan-tools` brings it along; Alpine's does not. Name the loader rather than relying on another package to install it.
- **An image with no venus driver still runs on the CPU.** Debian bookworm's Mesa has no venus, so Vulkan falls back to `llvmpipe`, a software renderer. Check the `deviceName` your program selects.

See [Run locally](/docs/local/) for the local server, [Images](/docs/guides/images/) for building the guest image and [Run commands](/docs/guides/run-commands/) for reading command output.
